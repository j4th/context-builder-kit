# Harvest 5 — v1.0.0 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land, as one PR whose verification block is green after every commit, the sixteen open
issues (#58's residue, #60–#74) and the whole-kit review's findings. Then release the kit as
v1.0.0, back-tagging the five earlier harvests, with a CHANGELOG that carries each release's sync
notes.

**Architecture:** This master file carries the constraints, the ownership map, the baseline
(Task 0) and the closing tasks (F1–F5). The work itself is ten cluster files under
`docs/superpowers/plans/2026-09-30-harvest-5/`, executed in order V1 → V10. Each cluster task is
one atomic commit that names the trace ids it closes. Every fixture lands in the commit whose fix
it pins, having first been run red against the unfixed file.

**Tech Stack:**
- Markdown (skills, rules, commands, templates).
- bash (hooks, the path helper, fixtures, the verification block).
- JSON (`settings.json`, `.mcp.json.example`).
- JavaScript (workflow scripts and `.mjs` stub harnesses).
- Python 3 (`agent-cost.py`, `run-arms-headless.py`, `review-trigger-fixture.py`).
- YAML (review-workflow templates, the kit's CI).

Tools the block and fixtures need: `bash`, `git`, `jq`, `node`, `python3`.

**Spec:** `docs/superpowers/specs/2026-09-30-cascade-kit-harvest-5-design.md`. Read it in full
before Task 0. The trace is `docs/superpowers/specs/2026-09-30-harvest-5-trace.md`, one row per
ask. Every task names the rows it closes, the spec cluster (V1–V10) and the decisions (D41–D62)
it implements.

## Global Constraints

- **The private target is never named** in any committed file, this plan included: not its name,
  its paths, its ticket keys, its commit shas or its stack. A hunk ported from it is re-authored
  generic. The two public targets (`j4th/you-are-hear`, `j4th/echosphere`) are named in the spec,
  the trace and these plans, never in shipped kit content (`.claude/`, `.github/`, `README.md`,
  `CLAUDE.md`).
- **Re-author, never merge raw.** A target's file carries that project's prose. Port the change
  onto the kit's text; never copy a target's file over the kit's.
- **The block is the gate after every commit.** Run
  `bash .claude/workflows/tests/run-verification-block.sh`. It extracts the block from
  `.claude/rules/cbk-conventions-reference.md` § Verification on every run, so it is never a stale
  copy. It must print `verification: kit sub-block complete` and `verification: done`, and exit 0.
- **Read the runner by content, never by position.** From V1.1 on, the runner's last lines include
  `run-verification-block-fixture` output, and each cluster adds fixture lines before the kit
  sentinel. So a step judges a run by `exit=0` and the presence of the lines it names:
  `bash .claude/workflows/tests/run-verification-block.sh 2>&1 | grep -E 'always-loaded total|WARN|VIOLATION|verification:'; echo "exit=${PIPESTATUS[0]}"`.
  A cluster step that still shows `| tail -N` is read the same way: the lines it expects must be
  present, and `exit` must match.
- **New checks append at the sentinels.** A kit-sub-block check goes on the line(s) immediately
  before `echo "verification: kit sub-block complete"`. A project-sub-block check goes immediately
  before `  echo "verification: project sub-block complete"`, which is indented two spaces.
- **Check syntax.**
  - A must-be-absent check uses `absent` with a bracket-split literal, e.g. `absent grep -rn "opinionate[d] profile" …`.
  - A positive chain is wrapped `{ …; } || { echo "<what is wrong>"; exit 1; }`.
  - Every check prints a message that names what failed.
- **Hooks.**
  - `bash -n` on every hook after editing it.
  - `set -uo pipefail`, never `set -e`.
  - `input="$(cat)"` is the first statement after `set -uo pipefail`.
  - No pipeline decides on a reader that can exit first: use here-strings.
  - No bash-4-only builtins (`mapfile`, `readarray`, `declare -A`); a stock macOS bash is 3.2.
  - Every header carries `Tier:` and `Depends:`.
- **Fixtures.** They need only `bash`, `git`, `jq`, plus `node` or `python3` for their own
  language. They run in throwaway trees under `mktemp -d`, never in the real checkout. A case that
  needs a tool the host lacks (`unshare`, GNU `stat`) prints `SKIP: <case> (<tool> unavailable)`
  and does not fail; a silent skip is a defect. Each fixture exits non-zero on any failed case,
  and prints the case name.
- **Red first, inside the commit.** A new or extended fixture is written first and run against the
  unfixed file, where it must FAIL with the named case. Record that output line in the PR-body
  "red-first" table. Then make the fix, the fixture goes green, and both are committed together.
- **Byte-parallel copies stay byte-parallel.** The block diffs each pair:
  - `.claude/commands/finish.md` ↔ `.claude/skills/rough-in/references/finish-command.md` below its
    `--- BEGIN TEMPLATE ---` marker;
  - `.claude/commands/finish-procedure.md` ↔ `.claude/skills/rough-in/references/finish-procedure.md`;
  - `docs/adr/` ↔ `.claude/skills/scaffold/references/adr-starters/`;
  - the four `references/backends.md` copies (after V9 adds that diff).
- **Commits.** Branch `feat/harvest-5-v1.0.0` (it exists; the spec is its first commit). One
  commit per task. Conventional Commits, the subject naming the cluster and the body listing the
  trace ids closed. Trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. No CI-skip
  marker on any commit.
- **Platform claims.** Every quotation or behaviour claim about Claude Code, GitHub, npm, Anthropic,
  Linear, Notion or Dependabot written into kit text is fetched raw (`curl -sL <url>`, or the page's
  `.md` form on `code.claude.com`) and matched with `grep -F` on the day it is written. It carries
  `<url>, read <YYYY-MM-DD>` beside it. Typographic apostrophes are normalised before matching.
  Nothing from memory.
- **Kit issues are cited as `context-builder-kit#N`** or not at all (D53). A bare `#58` in shipped
  content links to a target's own #58.
- **Size and budget.**
  - Every `SKILL.md` stays under 500 lines; the block enforces it.
  - Always-loaded rules target ≤ **130,628** bytes (D59). The block prints a non-failing `WARN` above
    **140,000** (D50).
- **Anchor edits on text, never on line numbers.** Line numbers in these plans are "at `74edf84`",
  for orientation only. Every edit is an exact-string replacement anchored on text that no other
  cluster's task changes (§ Ownership map). If an anchor is missing when a task runs, stop and
  reconcile; never guess.

## Decisions and observations taken while planning (for the PR body)

- **P1, observed live on 2026-09-30 (Claude Code 2.1.285).** The Bash tool ran
  `cd docs/superpowers/plans/2026-09-30-harvest-5`. A Workflow launch from the same session was
  then **blocked** by `require-repo-root-for-agents.sh`, which named that subdirectory as the launch
  directory. A hook's payload `cwd` follows the Bash tool's `cd`, as the hooks page now says
  ("`cwd` follows Claude … after Claude runs `cd`"). Harvest 3 recorded the opposite (2026-09-07).
  V2's probe-P1 step still runs its own controlled probe. This observation is the first data point,
  and it means the guard now fires on a `cd` into a subdirectory, not only on a session launched
  from one. The guard's header and the conventions' account of its trigger change accordingly
  (V2).
- **V1.4 keys the kit-sub-block `CLAUDE.md` check on `docs/cbk/blueprint.md` in a target.** A
  target before blueprint has no `CLAUDE.md` yet, since blueprint writes both files in the same
  phase, and the check made a fresh scaffold red forever. The residual: a brownfield target with a
  pre-existing `CLAUDE.md` goes unchecked until blueprint. That makes the check less strict, but it
  never produces a false red.
- **D61's breadth, stated for the operator.** A payload jq cannot parse makes
  `protect-main-branch.sh` refuse *every* Bash call carrying it, not only a commit, and makes
  `require-repo-root-for-agents.sh` refuse that dispatch. Such a payload is abnormal (a lone UTF-16
  surrogate is the known case). A refusal names the cause, and the operator's route is to retry
  without the unreadable text.
- **V7 reads the floor strictly:** a docs-only PR may skip the sweep, never the floor. That is
  consistent with § The floor, where the only waiver is break-glass. It corrects the reference
  half's docs-only anti-pattern.
- **`/pr-respond`'s author filter** trusts the PR's author. On a fork PR, that contributor's own
  comments can still reach Apply. The marginal risk is low, because they wrote the PR's code.
  Recorded, not changed.
- **Left for F2's triage:** scaffold and blueprint prose that still describes provisioning "via
  GitHub MCP" after D58 drops the GitHub MCP entry from `.mcp.json.example`; and
  `rough-in/references/handoff-to-finish.md:3`'s stale "bootstrap-finish" phrase.
