## Global Constraints

Identical to P3's, restated for the executor:

- **Sanitized, one-way.** No sibling repository, package, product, issue number or run id lands in kit content (the two public runs are named nowhere; the private instance never). Every lifted body is generalized to bracketed placeholders before it lands. Sibling repositories are read, never modified.
- **Portability greps are the hard gate.** The verification block (`cbk-conventions-reference.md § Verification`, kit sub-block) must be green after every task, extracted and run as in P3:

  ```bash
  awk '/^## Verification/{p=1} p' .claude/rules/cbk-conventions-reference.md | awk '/^```bash/{c=1;next} /^```/{c=0} c' > /tmp/claude-1000/cbk-verify.sh && bash -e /tmp/claude-1000/cbk-verify.sh
  ```

  New checks are plain lines inside the single fence; must-be-absent checks use `absent` with a self-splitting literal; positive chains are wrapped `{ … } || { echo …; exit 1; }`. The adr-starters mirror is diffed byte-for-byte against `docs/adr/` — any starter change lands in both.
- **Never commit on `main`; branch and first commit in separate tool calls.** No `[skip ci]`. One commit per task, Conventional Commits, the `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` trailer.
- **No unsourced platform claims**: a GitHub or Claude Code behaviour lands with its page and date, or as a dated field observation. The three the issues flag: the required-check path-filter cause (GitHub's troubleshooting page), the check-run rename consequence (field-observed — dated as such), the linguist generated-file list (`generated.rb` and `docs/overrides.md`).
- **Bounded fan-outs.** Task 10's sweep stays at or under 25 planned agents; no research workflow is launched (the research is the issue bodies and the sibling artifacts, already read).
- **Every `SKILL.md` stays under 500 lines** (the block enforces it); every always-loaded rule edit is measured and recorded in the PR body.

## Decisions taken while planning (for the PR body)

- **D-P4-1 — the `.github/` starters ship in one reference file** (`scaffold/references/github-starter-templates.md`) with the literal bodies, plus a kit-root `.github/dependabot.yml.example` (the kit itself has only the actions ecosystem; the example carries the floor for it and inactive stubs for the common lockfile ecosystems). The kit does not adopt a PR template or issue forms for itself — the kit's own PRs are `gh pr create --body-file` runs.
- **D-P4-2 — the review workflows are blueprint templates**, not scaffold starters: they need the project block (rules to check, guarded surfaces, docs-only paths, model and effort) that only blueprint knows. Scaffold's PR/review answer gates whether blueprint emits them.
- **D-P4-3 — the roadmap is emitted by blueprint on the github-issues and in-repo-markdown axes** (not on linear, whose projects carry sequence), read by framing, appended by framing, flipped by rough-in and by `/finish` on the PR's own branch as the last commit (P3's deferred clause), with the post-merge checklist as the fallback flip when the spec did not name it. No `/land` command (D23).
- **D-P4-4 — corrections.md is a starter in both homes**: `docs/adr/corrections.md` (the kit's own register, empty) and `scaffold/references/adr-starters/corrections.md` (byte-identical; the block already diffs the two trees).
- **D-P4-5 — the frozen-corpus pattern ships as prose plus a pointer to the ADR hook as the enforcement exemplar**; no `protect-frozen-corpus.sh` ships, because the kit cannot know a corpus path. Scaffold registers the enforcement set when consultation designated a corpus.
- **D-P4-6 — one MCP-configuration section lives in `tooling.md`** (the template), covering committed config with env-var references, the example env file, phase-justified wiring and the list-valued-keys rule; `workflows.md`'s optional cost section names money and agent-run quota separately.
